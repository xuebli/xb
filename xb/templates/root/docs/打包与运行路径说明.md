# 打包与运行路径说明

> 本文是生成项目的**构建产物、安装布局、运行时数据目录**完整速查。
> 三种运行形态（开发态 / 项目目录跑 PyInstaller 二进制 / DEB·NSIS 安装态）
> 各自的路径判定规则都在这里。`<package_name>` 是 `xb init` 的项目名
> （技术标识），`<DisplayName>` 是 productName（安装目录名，Linux `/opt` 与
> Windows Programs 目录用）。

---

## 一、三种运行形态（路径判定的总开关）

判定逻辑在 `backend/managers/path_manager.py` 的 `PathManager.__init__`：

| 形态 | 判定 | 配置/数据落点 |
|------|------|--------------|
| ① 开发态 | `sys.frozen` 为假（源码运行） | 全部在**项目目录**内 |
| ② 项目目录跑二进制 | `frozen` 且 `sys.executable` 的父目录名为 `dist` | 全部在**项目目录**内（与装好的 DEB 用户配置互不污染） |
| ③ 安装态 | `frozen` 且二进制在 `server-bin/` 下（DEB/NSIS 部署） | 资源读安装目录，配置/数据写**用户家目录** |

```
形态①  python backend/main.py            → configs/ datas/ scripts/ 都在项目根
形态②  ./dist/server                     → 同上，但 frontend/dist 直接复用
形态③  /opt/<DisplayName>/resources/server-bin/server → 资源在 /opt，数据在 ~
```

## 二、构建产物路径（`./build.py` 各阶段）

| 阶段 | 命令 | 产物路径 | 说明 |
|------|------|---------|------|
| 前端 | `-f` | `frontend/dist/` | Vite 构建输出；构建前清空重建 |
| 后端 | `-b` | `dist/server`（Windows `dist/server.exe`） | PyInstaller onefile；中间文件在 `build/backend/`，spec 在项目根 |
| Electron | `-e` | `electron/dist/*.deb`（Linux）/ `*.exe`（Windows NSIS） | electron-builder 输出；`build.py -a` 只取**最新**的一个安装包 |
| 发布信息 | `-a` 上传时 | `datas/update_ubuntu.json` / `datas/update_windows.json` | 动态字段（版本/说明/hash），build.py 产物，**不入 git** |
| 上传进度 | `-a` 上传时 | `datas/logs/upload_progress.json` | 上传子进程写的进度文件，供父进程渲染 |

`--update` 项目的 `./build.py --upload-only` 从 `electron/dist/` 里挑
最新的 `*.deb`/`*.exe` 直接上传，不重新构建。

### 打包进安装包的资源映射（electron/package.json `extraResources`）

| 项目内来源 | 包内目标（`resources/` 下） | 备注 |
|-----------|---------------------------|------|
| `dist/`（过滤 `server*`） | `resources/server-bin/` | PyInstaller 后端二进制 |
| `frontend/dist/` | `resources/frontend/` | 前端静态资源 |
| `configs/` | `resources/configs/` | **`secrets.yaml` 与 `*.bak` 永远排除**；`*.example` 混淆后随包 |
| `resources/polkit/` | `resources/polkit/` | 标配；postinst 部署到系统路径（`install-update` 分支仅 `--update` 项目） |
| `scripts/` | `resources/scripts/` | 首次启动拷到用户 scripts 目录 |

## 三、安装布局

### 3.1 Linux（DEB）

```
/opt/<DisplayName>/                      # electron-builder 安装根
├── <package_name>                       # Electron 主程序（postinst 注册到 PATH）
├── chrome-sandbox                       # postinst 强制 setuid 4755（Ubuntu 24.04+ 必需）
└── resources/
    ├── server-bin/server                # 后端二进制（形态③判定点：父目录名 server-bin）
    ├── frontend/                        # 前端静态资源
    ├── configs/                         # 打包内置配置（*.example）
    ├── scripts/                         # 捆绑脚本
    └── polkit/                          # 特权三件套源文件（postinst 装完即复制走）
/usr/bin/<package_name>                  # update-alternatives 注册的命令入口
/usr/local/share/<package_name>/privileged-helper        # root 白名单执行器（polkit 标配）
/usr/share/polkit-1/actions/com.<package_name>.privileged.policy
/etc/polkit-1/rules.d/60-<package_name>-privileged.rules
```

### 3.2 Windows（NSIS）

```
C:\Users\<用户>\AppData\Local\Programs\<DisplayName>\   # perMachine=false 默认目录
└── resources\server-bin\server.exe、frontend\、configs\、scripts\
```

安装时可勾选更改目录（`allowToChangeInstallationDirectory`）；
卸载器默认**不删**用户数据，勾选"删除用户数据"才清理
`C:\Users\<用户>\AppData\Roaming\<package_name>\` 与
`C:\Users\<用户>\AppData\Local\<package_name>\`，升级不触发删除。

## 四、运行时数据路径（安装态，形态③）

| 内容 | Linux | Windows | macOS |
|------|-------|---------|-------|
| 配置目录（`config_dir`） | `~/.config/<package_name>/` | `C:\Users\<用户>\AppData\Roaming\<package_name>\` | `~/Library/Application Support/<package_name>/` |
| 运行数据根（`data_dir`） | `~/.local/share/<package_name>/datas/` | `C:\Users\<用户>\AppData\Local\<package_name>\datas\` | 同配置目录下的 `datas/` |
| └ 日志 | `datas/logs/` | 同左 | 同左 |
| └ 报告 | `datas/reports/` | 同左 | 同左 |
| └ 更新包缓存 | `datas/updates/` | 同左 | 同左（Linux 是 polkit 安装白名单唯一路径） |
| └ 配置备份 | `datas/config_backups/<版本>_<时间戳>/` | 同左 | 同左 |
| 用户脚本（`scripts_dir`） | `~/.local/share/<package_name>/scripts/` | `C:\Users\<用户>\AppData\Local\<package_name>\scripts\` | 同配置目录下的 `scripts/` |
| 前端/内置配置/内置脚本 | 安装目录 `resources/` 下（只读） | 同左 | 同左 |

要点：

- **配置初始化**（`init_user_configs`，仅安装态）：首次启动把包内
  `resources/configs/` 递归拷到配置目录，`*.example` 拷贝时**去后缀**；
  已存在的文件不覆盖（`--update` 项目对 yaml 递归补齐缺失键，日志打
  `[补齐] 文件名: 键`，覆盖前留 `.bak`）；
- **安装包里的 `secrets.yaml.example`** 是唯一随包分发的密钥模板，
  真实 `secrets.yaml` 永不进包；安装后 secrets.yaml 权限收紧为 600（postinst）；
- **形态②例外**：在项目目录跑 `dist/server` 时，内置配置与用户配置是
  同一个 `configs/`，初始化逻辑会自动跳过（不把 example 拷到自己旁边）。

## 五、开发态路径（形态①②，项目目录内）

```
demo/
├── backend/main.py           # 后端入口（uvicorn，端口读 configs/global_config.yaml）
├── frontend/dist/            # -f/-a 前端构建产物；开发态后端 SPA 兜底也读这里
├── dist/server(.exe)         # -b/-a 后端 PyInstaller 产物
├── build/backend/            # PyInstaller 中间文件（可删）
├── electron/dist/            # 安装包输出目录
├── configs/                  # global_config.yaml / secrets.yaml(+example)
│                             # --update 项目另有 config_changes.json
├── datas/                    # 运行时数据（gitignore）
│   ├── logs/                 # backend.log / frontend.log（--update 另有
│   │                         #   update_install.log / upload_progress.json）
│   ├── pids/                 # dev.py 的 PID 文件
│   ├── updates/              # --update：更新包下载缓存（polkit 安装白名单路径）
│   └── config_backups/       # --update：升级前配置备份
├── scripts/                  # 捆绑脚本（example.py；--update 项目另有 feishu_upload.py）
└── docs/                     # 说明文档（本文件等）
```

> `firmwares/`、`external/` 等资源目录按实际需求新增（AGENTS.md 约定禁止
> 预声明占位目录），`path_manager` 的对应取值方法仅在目录存在时可用。

dev 模式日志：`python dev.py start` 后看 `datas/logs/backend.log` 与
`datas/logs/frontend.log`。

## 六、速查：一个文件从构建到落地的旅程

以 `configs/secrets.yaml.example` 为例：

```
configs/secrets.yaml（真实值，gitignore，只在发版机）
  → build.py 深合并 → secrets.yaml.example（敏感键混淆 obf1:）
  → extraResources: resources/configs/secrets.yaml.example → DEB /opt/<DisplayName>/resources/configs/
  → 首次启动 init_user_configs → ~/.config/<package_name>/secrets.yaml（去后缀，0600）
  → 升级时：安装迁移读旧包 example → 首启补齐读新包 example（值自动解混淆）
  → 构建结束 example 恢复留空模板（明文 secrets.yaml 不进包；obf1 混淆值可逆）
```
