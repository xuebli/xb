# 版本管理说明

> 本文解释生成项目的**版本号管理机制**：版本号在哪里、为什么 commit 时会
> 弹窗、弹窗没出现怎么办、以及**为什么绝对不能跳过这个 hook**。

---

## 一句话总览

```
git commit → pre-commit hook 弹出版本选择（GUI / Web）
  → 选 patch / minor / major（或跳过）
  → hook 自动 bump 并同步所有版本文件 → 提交继续
```

---

## 一、版本号 single source of truth 与同步文件

**版本号唯一权威来源是 `electron/package.json`**，bump 时自动同步其余文件：

| 文件 | 是否总是同步 | 说明 |
|------|-------------|------|
| `electron/package.json` | ✓ | 权威来源，electron-builder 安装包版本取这里 |
| `pyproject.toml` | ✓ | Python 侧版本声明 |
| `electron/package-lock.json` | ✓ | 根级 + `packages[""]` 两处；不同步会被 npm install 改写产生脏 diff |
| `backend/app_version.py` | 仅 `--update` 项目 | 打包态后端读不到 package.json，靠它取当前版本（应用内更新接口用） |

提交时的选择弹窗（三模态，自动判断运行环境）：

| 环境 | 判定 | 交互方式 |
|------|------|---------|
| 本地图形会话 | 有 `DISPLAY`（X11）或 Windows | Tk 弹窗，直接在屏幕上操作 |
| 远程 IDE / SSH | `VSCODE_IPC_HOOK_CLI`、`SSH_CONNECTION/SSH_CLIENT/SSH_TTY` 任一存在 | 终端输出 **Web 地址**，在本地浏览器打开操作 |
| 纯终端（无图形、无 SSH） | 以上都不满足 | 自动跳过版本选择，commit 正常进行 |

选项：**patch**（默认）/ **minor** / **major** / **跳过**（直接提交，不 bump）。

## 二、日常使用

**hooks 无需手动安装**：`./dev.py start` 首次启动及每次启动都会自动安装
Git hooks，之后正常提交即可触发版本弹窗：

```bash
./dev.py start                    # hooks 自动装好（polkit 特权入口也一并自动部署）
git commit -m "feat: add new feature"   # 自动弹出版本管理界面（SSH 输出 Web 地址）
```

`./version/scripts/install_hooks.py` 仅在特殊场景需要手动执行
（例如删除过 `.git/hooks`、换过 `core.hooksPath`、CI 环境没有跑过 dev.py）：

```bash
./version/scripts/install_hooks.py   # 手动补装（一般用不到）
```

- bump 类型按语义选：修 bug/小改动 → `patch`；新功能 → `minor`；
  不兼容变更 → `major`；
- `版本迭代日志.md`（变更记录）随提交一起维护；版本文件自身的改动
  不会再次触发 hook（防止递归弹窗）；
- hook 安装的是 **sh 转发脚本**（指向项目内 `version/hooks/pre-commit.py`，
  优先用项目 `.venv` 的 Python）——转发脚本由 install_hooks.py 生成，
  **勿手动修改**；改 hook 逻辑直接改 `version/hooks/pre-commit.py`，立即生效。

## 三、纪律：永远不要绕过 hook（与 AGENTS.md §G 一致）

`git commit --no-verify` / `-n`、临时 `chmod -x .git/hooks/pre-commit`、
`core.hooksPath=/dev/null` 等**一律禁止**——跳过 hook = 版本号漏 bump、
各文件版本失同步（升级比对会出错）、变更记录缺档。

hook "看起来卡住"的正确处理（按优先级）：

1. `echo "DISPLAY=$DISPLAY SSH_CLIENT=$SSH_CLIENT VSCODE_IPC_HOOK_CLI=$VSCODE_IPC_HOOK_CLI"`
   确认走了哪条模态分支；
2. 本地图形环境 → 弹窗在物理屏幕上，去屏幕完成它；
3. 远程 SSH/远程 IDE → 复制终端输出的 Web 地址到**本地浏览器**打开；
4. 页面启动失败或超时 → commit 会中止，修复交互环境后重新提交。

AI 编码助手注意：bash 工具会等 hook 弹窗结束才返回，用户没及时操作可能
超时——应提醒用户完成弹窗，而不是绕过。

## 四、FAQ

**Q：提交时什么都没弹，直接提交成功了？**
当前环境是纯终端（无 DISPLAY、无 SSH），hook 判定无法交互，静默跳过版本
选择。这是预期行为；需要记录版本时在图形环境或 SSH 会话里提交。

**Q：误点了"跳过"，这个版本号还能补吗？**
能。直接调 version_manager 的 CLI 补 bump，然后提交版本文件（弹窗出现时
选"跳过"，版本文件自身的改动不会再次触发 bump）：

```bash
python version/scripts/version_manager.py patch   # 或 minor / major
git add -A && git commit -m "chore: bump version"
```

**Q：想手动改版本号怎么办？**
改 `electron/package.json` 后手动同步其余文件容易漏（lock 文件有两处、
`--update` 项目还有 `app_version.py`）。用上面的
`version/scripts/version_manager.py <patch|minor|major>` 一条命令同步全部。

**Q：CI / 脚本环境里 commit 被弹窗卡住？**
纯终端环境会静默跳过，不会卡；若卡住说明环境变量让 hook 误判为远程会话，
按第三节第 1 条排查环境变量。
